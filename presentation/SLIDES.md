# Safe to Be Challenged — Presentation (5 min, 20 slides)

Use this outline to build the deck (e.g. with MCP pptx tools or Keynote/PowerPoint).

---

1. **Title** — Safe to Be Challenged: Trust and Harmlessness in Adversarial AI Advising  
2. **Problem** — AI feedback can be harsh; we want challenge without harm.  
3. **Problem (cont.)** — Users need to know when harmlessness is being monitored.  
4. **Research question** — Does making harmlessness visible change reliance and engagement?  
5. **Design: three conditions** — Committee only / Silent monitor / Visible label.  
6. **Design: committee** — Skill Diagnostician → Adversarial Critic → (optional) Harmlessness Monitor.  
7. **Design: digital doubles** — Thesis, condition, trust sensitivity, methodology from MACSS corpus.  
8. **Design: data** — MACSS theses, abstracts, GitHub memos (longitudinal).  
9. **Design: metrics** — Mechanical reliance, trust (engagement), quality.  
10. **Method summary** — Pipeline: load corpus → build doubles → run conditions → compute metrics.  
11. **Results: pilot** — Mean mechanical reliance by condition (chart).  
12. **Results: pilot** — Mean trust by condition (chart).  
13. **Results: table** — MR, trust, quality by condition (sample sizes).  
14. **Results: GitHub** — Longitudinal trajectories (if run).  
15. **Qualitative** — Feedback–revision pairs in qualitative_samples.json; engagement, harmlessness, reliance.  
16. **Interpretation** — Visible label: possible trade-offs between engagement and over-reliance.  
17. **Limitations** — Simulated students; small N; placeholder label.  
18. **Future work** — Scale N; human subjects; harmlessness rubric; replication.  
19. **Summary** — Safe to be challenged = visible harmlessness + adversarial feedback; pipeline and validation in place.  
20. **Thank you / Q&A** — Contact / repo / report.md.
